# Public filter and UI implementation

Date: 2026-10-10. Current implementation follows [public filtering architecture](../architecture/public-catalog-filtering.md) and [decision 022](../decisions/022-public-catalog-filter-scope.md).

Root causes corrected: exact Category matching and filter policy scope did not include descendant leaves; CHOICE could not express OR selections; missing totals and a four-item page assumption conflicted with twelve-item requests. Catalog now resolves scope inside its own Prisma transaction, validates public policy in a batch, validates available option ownership, uses typed SQL predicates and counts the matching result set. The shared client normalizes filters and cache identity, URL history retains intent, and paging retains the full filter scope. No schema or existing business data migration is required.

Public composition now reuses shared category/product grids, 4:3 frames, contextual Category hero, unified detail gallery and localized Group specifications. Home no longer uses fixed editorial spanning rows or giant featured Products. Listings have hierarchical Category browsing, dynamic checkbox/range/boolean/text fields, removable chips, live count and mobile drawer. Removed inherited mobile image height that conflicted with ratios. Existing colors, typography, container, drawer, focus and reduced-motion primitives remain authoritative.

Verified: service build, backend/frontend types, 41 backend units, 10 frontend behavior checks, all 67 Catalog integration tests, 14 architecture enforcement probes and installed 71-model/714-column/76-FK schema parity. Real API/browser verification passed parent/leaf/OR/range combinations, true empty results, pagination and URL refresh/back/forward; staff publication/value edits and Category moves; API error without fallback; six viewports and Arabic/Sorani layouts. All three real-API browser tests and five retained public/keyboard browser tests pass with zero skips, failures or flaky results. Fourteen reviewed screenshot baselines replay without updates. The final fifteen-test PostgreSQL run also verifies global Gold filtering and deterministic localized facet order. Mobile related Products now use the shared Product grid and documents occupy the full mobile column. See [timestamped acceptance evidence](../validation/public-catalog-2026-10-10T08-13-50-170Z.json).

Compatibility: singleton optionId and legacy category query aliases are strict normalized inputs to the same endpoint. Explicit demo mode remains a development fixture, never an API failure fallback. Historical validation is retained. Normal databases/files were read only for parity; mutation tests use disposable service fixtures and clean them up. Bounded per-Product projection queries remain; production provider/load/hosted CI/deployment acceptance is outside this request.
