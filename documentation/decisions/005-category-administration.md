# 005: Category navigation and branch concurrency

Accepted 2026-10-04 for B4. Keep the existing databases, pinned dependencies and reviewed SQL; no schema migration is needed.

Admin reads use a consistent Catalog transaction and the ancestor-aware `live_categories` view. Lists load at most 100 children per page. Breadcrumbs page from root to the selected category without a business depth limit. Move destinations reuse child navigation, exclude the source subtree and product-bearing parents, and expose root separately. Admin DTOs include saved translations and explicit missing locales alongside localized display fields.

The schema has category row versions and a private write gate, but no public root-list revision. Use scope-bound SHA-256 content preconditions over the parent version, all active sibling IDs/versions, saved translations and directly attached products. Root scope uses the same strategy with a null parent. Tokens are concurrency guards, not authorization or access to the gate. They invalidate conservatively when a sibling is edited. Cursor scope includes parent, locale, query purpose, source for destinations, and list revision. Breadcrumb cursors bind the complete ancestor path revision. No timestamp is converted to a lossy cursor key.

Move uses an explicit destination parent (null means root), `beforeId` (null means append), source version, and both sibling-list preconditions. Recheck ancestry, active state and product eligibility in the Serializable transaction. Same-parent moves are supported; a request already at that position commits no update/event. Allocate an exact bigint gap where available. If ties or bigint boundaries leave no gap, normalize only that destination sibling set, with a 500-row operational bound and an explicit 422 error beyond it. Complete-set atomic reorder has a 500-row request bound and checks exact membership. Child lists and ordinary gap-based moves have no sibling-count limit. These limits bound a transaction, not business hierarchy depth or the number of root categories. Discard list cursors after a mutation.

Reorder advances changed category row versions and the parent version when present. Its bounded event uses the parent as the aggregate anchor for nested lists, or the first changed category for roots; both anchors have a real advanced row version. The event also carries the resulting list revision. There is no invented monotonic version for root lists.

Deletion preview fingerprints all active branch categories/products and their owned translations, code reservations, specifications, media and technical attachments, plus referenced media/sheet versions. The read is consistent and has no side effects. Confirmation recomputes the fingerprint inside the deleting transaction before invoking the existing `soft_delete_branch` function and v1.1 owner hooks. Preserve the function's single outbox record and ID, normalize its payload into the versioned event contract in the same transaction, and retain shared sheets, registrations, files and reserved codes. Repeated deletion is 404. Media delivery revocation remains B5 work.

All writes remain on a single Prisma Serializable transaction client with bounded whole-transaction retries; fresh retries recheck the original client preconditions. External effects are absent. PostgreSQL [Serializable isolation](https://www.postgresql.org/docs/18/transaction-iso.html) and Prisma [parameterized raw queries](https://www.prisma.io/docs/orm/v7/prisma-client/using-raw-sql/raw-queries) support the existing transaction/SQL approach.
