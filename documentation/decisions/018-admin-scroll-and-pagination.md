# 018 — Admin collection scrolling and pagination

Date: 2026-10-08. Status: implemented; execution evidence belongs to the dated completion report.

Staff navigation uses Expo's publicly exported unstyled `Navigator`/`TabRouter` with `fullHistory`. Query navigation reuses the mounted route and records its parameter history. Ordinary stack pushes remounted the list, defeating previous-data loading and discarding local selection; same-route stack navigation replaced history. The staff-only full-history router satisfies both requirements without native-history patches or private imports. Invalid-query normalization uses in-place `setParams`, replacing the current history entry. The public website retains its existing router.

The installed TabRouter also deduplicates successive navigation to the same route key even under `fullHistory`. A focused `StaffRouter` decorator retains the previous history entry only when `NAVIGATE` changes parameters on the same mounted key. It delegates route parsing, authorization boundaries, rehydration, Back and other actions to the public base router. Partial states are passed through. `SET_PARAMS` normalization does not append an entry. Browser tests verify the resulting history, retained rows and real role checks; no vendored library patch is used.

Attributes and Groups inherited a sticky master list even though their collection layout had become a single-column grid. The entire table painted across the following empty detail canvas, exposing its border and “Choose” caption among rows. Configuration collections now use a static table and render selected-record details only when selected. The document is the primary vertical scroll container. An unconstrained horizontal wrapper handles wide tables; Category tree navigation, editor rails and modal/drawer scrolling retain their deliberately scoped behavior. Existing command-bar/sidebar stacking is preserved. No global border, focus, shadow or z-index workaround is introduced.

`GLDataPagination` is the shared presentational control. It receives localized labels and callbacks, shows the actual range/count, supports 10/25/50/100 rows (default 25), loading/disabled states, keyboard interaction and compact RTL/mobile controls. The existing public `GLPagination` is unchanged. The Admin adapter owns URL state and query normalization; the shared UI package does not depend on Expo routing or APIs.

Attributes, Groups and Units gain a bounded numbered collection query through a focused Catalog application port and Prisma adapter. Code/translation, type, visibility and lifecycle filters run before count/page selection. Count and rows execute on the same existing serializable Catalog unit of work. Stable ordering is code/ID (units use their unique code). Invalid query bounds are rejected and out-of-range numbered pages clamp to the last valid page. The legacy resource-bound cursor API remains available for selectors. Numbered mode costs an indexed/filtered count and offset scan; it enables direct navigation for these small configuration dictionaries without replacing every cursor contract.

Products retain ID or filter-bound manual bigint/ID keysets; Media retains ID keysets; the staff directory retains exact created-at microsecond/ID keysets. These APIs add owning-service filtered totals. Media additionally performs server filename search and one-row lookahead so the final page has no next cursor. Identity's directory count/page uses an opt-in repeatable-read snapshot; existing mutation transactions retain read-committed isolation and lifecycle policy. Count/page never reads another service's database. No SQL migration or ORM synchronization is needed.

The browser adapter preserves cursor boundaries in URL navigation state, providing Previous/Next, browser history and refresh without fetching all rows or pretending unvisited cursors are offset page numbers. Filters and page size reset the boundary history. Query keys include request state and retain prior data during fetches. Empty cursor pages after deletion step back to the preceding valid page; server-normalized numbered pages replace invalid URL state. Existing mutation invalidation refreshes the current query without a document reload. Count and cursor range can shift when concurrent records are added/deleted; this is normal keyset navigation, not a long-lived database snapshot across user actions.

Short cursor histories are portable URL state. Larger histories move into tab-scoped session storage behind an opaque URL key, keeping refresh URLs below ordinary HTTP header limits. The cache contains navigation boundaries, not credentials or authorization capabilities. Same-tab Back/refresh retains the history; opening such a long-history link in a different tab cannot reconstruct its visited boundaries and normalizes to page one. Storage-restricted browsers fall back to URL histories. This is a navigation cache, not persisted business data.

Media pickers and asset usage reuse the same controls with local state. Usage retains its existing bounded offset API and does not fabricate a total the contract does not expose. A full usage page allows probing the next page; an empty response steps back. Hierarchical Category collections retain recursive branch cursors and Load more actions, because flattened numbered pages would lose tree context.

Confirmed configuration deletion cancels and evicts the deleted detail query before list invalidation, then clears the selection. The reviewed-change component exposes a successful-commit cleanup callback; it does not run on previews or rejected writes. This prevents a stale detail refetch/404 while allowing the paginated collection and counts to refresh through the existing mutation mechanism.

Verification uses disposable PostgreSQL, real owning services/Gateway, authenticated browser interactions, before/after screenshots and computed scroll styles. Normal staff accounts and catalog data are not altered by these fixtures. See the [baseline](../implementation/admin-scroll-pagination-baseline.md) and completion report for actual results and limitations.

All four collection renderers expose the shared table state's optional Retry callback. It refetches their current keyed request rather than reloading the page or resetting its filters. Slow-request tests hold transport continuation while the owning service remains real; outage tests stop/restart the disposable Catalog HTTP server. Expected outage HTTP errors are asserted separately from clean authenticated-screen console checks.
