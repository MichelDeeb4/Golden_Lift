# Proposed ERP module boundaries

Date: 2026-10-10. All new modules below are design only. A module is a business boundary, not automatically a microservice. Phase numbers follow this baseline, not older B milestones or the earlier tenancy audit.

Each row names the proposed single writable authority. Interfaces/events are conceptual vocabulary, not implemented DTOs/routes. Local state and applicable outbox intent commit together; multi-owner operations use explicit idempotent coordination, not cross-service repositories or distributed SQL transactions.

## Shared foundations and exclusions

Media remains byte authority for documents/images across future owners; generic owner contracts need approved scope/version changes. Global user identity can be shared; writable business partners, units, tax and catalog definitions must have explicit tenant/company ownership. Accounting/customer billing and platform subscription billing are separate concepts.

No Accounting, Inventory, Purchasing, Sales, Subscription, Provisioning or new service is implemented by this task. No universal entity/repository framework or speculative schemas are needed to document these boundaries. Future intercompany workflows require explicit company authority and balanced local financial records; see [organization](organizational-model.md).
