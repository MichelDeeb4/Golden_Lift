## Security model limits

RLS narrows data access under trusted application context and catches missed filters; a compromised shared runtime credential/application that can set tenant context has a wider blast radius. Tenant isolation also depends on request authentication, parameterized SQL, capabilities, grants, functions/views, storage and operational authority. Dedicated tenant databases remain an option if stronger credential isolation is later required.

PostgreSQL documents that uniqueness/FK checks bypass row security, so same-tenant composite relationships and safe API conflict errors are required; RLS alone is insufficient. [PostgreSQL row security](https://www.postgresql.org/docs/18/ddl-rowsecurity.html). Public published data is intentionally public within its resolved company, but that does not make another company's drafts, counts, usage or private source files public.
