# Implementation roadmap

Date: 2026-10-10. Proposed work only. **Do not execute these phases until approved.** Inventory management is excluded throughout. Current audit is complete when these five documents are delivered; approval is required before implementation.

## Release sequence and safety gates

Current state: global Identity roles and company data, service-owned Prisma/SQL, no trusted tenant context or RLS. Root cause: ownership and authorization contracts model one company. Target: [03](03-proposed-target-architecture.md), with the full dependency inventory in [02](02-multi-tenancy-impact-analysis.md).

Order: Phase 0 → 1 → 2 → 3 → 4 → 5 → 6 → 7 → 8. Subtasks inside a phase can be independently reviewed, but no second company is activated until all isolation paths and end-to-end gates pass. A feature hidden by navigation is not an isolation gate. Keep each slice coherent; do not expose tenant routes while dependent persistence/workers remain global.

Use reviewed SQL expansion and service-specific clients; preserve existing migration history. Snapshot the actual uncommitted baseline before implementation. Every code phase runs build, strict types, format, architecture checks and affected unit tests; schema/security/transaction phases additionally require disposable real PostgreSQL and owning HTTP/process checks. Browser mutations must persist and survive reload/read API verification. Record fresh dated results, never relabel historical reports.

A coordinated pre-production maintenance cutover is the recommended default: pause writers/workers, backup all owning databases plus private storage/key manifests, migrate with ambiguity checks, then resume only compatible binaries. Rollback after accepting multiple tenants cannot run old global binaries against new data. Use a tested forward fix or coordinated snapshot restore; storage deletion/copy side effects and queue checkpoints must be included.
