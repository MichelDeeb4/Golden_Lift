## Application, packages and process roles

The Expo application contains public routes plus /admin, /super-admin and /component-lab. Staff/public query composition is separate. Browser history/draft guards use web globals; native readiness is not proven. [Tests](../../tests) include client/CRUD unit and browser workflows.

contracts owns portable transport types/errors/validators; platform owns technical config/HTTP/retry/SQL/relay adapters; api owns validated public/staff clients. catalog-ui/i18n/icons/tokens/ui own presentation. None is a catch-all ERP business owner. All fourteen workspace names resolve in manifests, lockfile and aliases.

Media's [worker](../../services/media/src/composition/worker.ts), [relay](../../services/media/src/composition/events.ts) and Catalog's [relay](../../services/catalog/src/composition/media-events.ts) need their own deployment lifecycle and credentials. Local scanner/native/signed HTTP readiness was executed. Hosted SMTP/S3/RabbitMQ, containers and load acceptance remain separate; health does not prove them.
